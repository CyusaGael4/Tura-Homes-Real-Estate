# TuraHomes Real Estate

A responsive, multi-page real estate website for exploring property listings in Kigali, Rwanda.
Visitors can browse and filter sample homes, view property details, learn about TuraHomes'
services, and prepare an enquiry using their email app.

The site is built with React and Vite. Property listings are currently local demonstration data;
the app does not connect to a live database or submit enquiries to a server.

## Features

- Home page with featured listings, search filters, company highlights, and calls to action.
- Property catalogue with category, property type, and location filters. Filters are reflected in
  the URL and can be bookmarked or shared.
- Detail page for every listing, with price, location, property features, and enquiry links.
- About, Services, and Contact pages.
- Responsive navigation with a mobile dropdown and animated menu control.
- Motion effects, reduced-motion-aware number counters, and image fallbacks.
- Local sample listings and images, so the site works without API credentials.

## Technology

- React 18 and React Router
- Vite 5
- Tailwind CSS 4
- Framer Motion
- Lucide React

## Requirements

- Node.js 18 or newer
- npm (included with Node.js)

Check the installed versions:

```sh
node --version
npm --version
```

## Set up locally

From the project directory, install the exact dependency versions in the lockfile and start the
development server:

```sh
npm ci
npm run dev
```

Open the local URL printed by Vite (normally `http://localhost:5173`). Vite may choose another
available port if that one is already in use.

To make a production build and preview it locally:

```sh
npm run build
npm run preview
```

The production-ready static site is written to `dist/`. The `dist/` directory is generated by the
build and should not be committed.

## Using and updating the site

### Browse listings

Open **Properties** from the navigation or use the search form on the home page. Filter by category,
property type, and location. On the Properties page, filters update the URL, so a filtered view can
be shared directly. Select **View details** to open a listing.

### Update sample listings

Edit `src/data/demoProperties.js` to add or change the demonstration listings. Each listing should
have a unique `id` and can include:

- `title`, `description`, and `image`
- `price` and `currency`
- `category` (for example, `Buy`, `Rent`, `Sell`, or `Invest`)
- `type` (for example, `Apartment`, `House`, `Villa`, `Commercial`, or `Land`)
- `location`, `city`, `bedrooms`, `bathrooms`, `area`, `featured`, and `status`

Put runtime-served listing images in `public/assets/` and use paths such as
`/assets/property-name.jpg`. The About page image is imported from `assets/` and bundled by Vite.
If a listing image fails to load, the site uses a local fallback image.

### Contact enquiries

The contact form prepares an email draft addressed to `hello@turahomes.rw`; it does not send or store
the enquiry. The visitor must send the draft from their own email application.

## Project structure

```text
assets/                 Images bundled into the app by Vite
public/assets/          Static images and the site logo
src/
  components/            Shared navigation, cards, filters, and motion effects
  context/               Shared local property data and filtering
  data/                  Demonstration property listings
  lib/                   Property formatting, normalization, and image helpers
  pages/                 Home, Properties, Property Detail, Services, About, Contact
  App.jsx                Routes and shared page layout
  main.jsx               React entry point
```

### Deploy the website

The built app is static and can be hosted by services such as Vercel or Netlify. Connect the project
to your chosen hosting provider, use `npm ci` as the install command and `npm run build` as the build
command, and set `dist` as the publish/output directory. The app uses React Router, so configure the
host to serve `index.html` for page-route requests; otherwise direct visits or refreshes on routes
such as `/properties` may return a 404.

GitHub Pages is also possible, but a project site needs a matching Vite base path and a single-page
app route fallback. Configure and test those before selecting Pages as the production host.
